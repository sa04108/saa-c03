# 대화 맥락과 입력 예산

## 현재 적용된 동작

하나의 세션은 `ai_conversations`의 학습 자료(`context`)와 그 세션의 `ai_chat_turns`를 유지합니다. 기록 화면에서 세션을 선택하면 같은 자료와 대화로 돌아갑니다. DB에는 전체 기록이 남지만, 모델에는 다음 범위만 전달합니다.

- 선택한 세션의 학습 자료: 본문 최대 12,000자
- 같은 세션의 최근 질문·답변 3쌍: 메시지마다 앞부분 최대 2,000자
- 이번 질문: 최대 2,000자
- 시스템 지침·검색 도구 정의, 실제 검색한 경우 Tavily 발췌: 최대 5개 × 1,600자와 출처 정보

브라우저 요청 본문은 UTF-8 기준 64 KiB까지 허용하므로 각 필드의 문자 수 제한보다 먼저 이 한도에 닿을 수도 있습니다. 문자·바이트·토큰은 서로 다른 단위입니다. 특히 한글에 영문 기준의 ‘4자 = 1토큰’ 추정을 그대로 적용하면 안 됩니다.

현재 자동 요약은 없습니다. 오래된 내용은 저장소에서 삭제되는 것이 아니라, 모델에 전달하는 최근 3쌍에서 빠집니다. 따라서 긴 세션의 초반에 합의한 조건을 AI가 계속 기억한다고 보장할 수 없습니다. 이번 세션 목록 UI 변경은 이 전달 범위를 바꾸지 않습니다.

## Google에서 확인한 모델 한도

2026-10-31에 `GET https://generativelanguage.googleapis.com/v1beta/models/{model}`로 조회한 `inputTokenLimit`·`outputTokenLimit` 값입니다. [공식 Models API](https://ai.google.dev/api/models)를 기준으로 하며, 모델 변경 시 다시 확인해야 합니다.

| 모델 | 최대 입력 토큰 | 최대 출력 토큰 |
| --- | ---: | ---: |
| `gemini-3.8-flash` | 1,048,576 | 65,536 |
| `gemini-3.6-flash` | 1,048,576 | 65,536 |
| `gemini-3-flash-preview` | 1,048,576 | 65,536 |
| `gemini-3.5-flash-lite` | 1,048,576 | 65,536 |
| `gemini-3.1-flash-lite` | 1,048,576 | 65,536 |

이는 모델이 지원하는 최대 크기이며 무료 프로젝트의 TPM·RPM·RPD와는 별개입니다. 현재 앱은 대화 출력 4,096토큰, 예상 질문 출력 2,048토큰을 요청합니다. 큰 입력이 허용된다고 해서 무료 할당량 안에서 빠르게 응답한다는 뜻은 아닙니다. 모델별 Gemini 호출 시간 합계 5초 제한도 그대로 적용됩니다.

## 압축 도입 검토안 — 아직 구현하지 않음

현재의 제한된 전송 범위는 모델 최대 입력 크기보다 훨씬 작습니다. 자동 압축을 도입하는 목적은 최대치에 가까운 입력을 채우는 것이 아니라, 비용을 관리하면서 오래된 대화의 중요한 조건을 유지하는 것입니다.

다음 수치는 초기 운영안이며, 실제 입력 토큰 측정과 응답 시간에 따라 조정해야 합니다.

1. 모델 공통 입력 예산을 **16,000토큰**으로 시작합니다. 시스템 지침·학습 자료·요약·최근 원문·현재 질문·도구 정의·검색 결과를 모두 포함합니다. fallback 후보 중 가장 작은 입력 한도도 넘지 않아야 합니다.
2. 약 **12,000토큰**에 도달하면 오래된 질문·답변 쌍을 요약 대상으로 삼습니다. 최근 3쌍과 현재 질문은 가능한 한 원문으로 남기고, 요약은 최대 **2,000토큰**으로 유지합니다. 자료 자체가 크면 질문에 필요한 구간을 선택해야 하며, 대화 요약만으로 충분하다고 가정하지 않습니다.
3. 요약은 세션별로 저장해 다음 요청에서 재사용합니다. 합의한 요구사항·숫자·결론·미해결 질문·정정 내용을 보존하고, 원본 질문·답변은 변경하지 않습니다. 다른 세션의 요약은 섞지 않습니다.
4. 저장 시 마지막으로 요약한 턴과 요약 버전을 함께 기록합니다. 같은 세션의 동시 요청이나 늦게 끝난 요약이 더 최신 결과를 덮어쓰지 않도록 원자적으로 갱신해야 합니다.
5. 요약 생성은 추가 모델 호출과 토큰을 소비하므로 매 질문마다 실행하지 않습니다. 답변과 별도로 처리하더라도 실패·대기 중 사용할 맥락 범위를 정의해야 합니다. 실패 시 원문을 삭제하거나 모델별 5초 제한을 늘리지 않습니다.
6. 토큰 수는 단순 문자 수로 확정하지 않습니다. [CountTokens API](https://ai.google.dev/api/tokens) 등으로 임계값 근처의 실제 입력을 확인하되, 매 요청의 추가 통신 비용도 고려합니다. 압축 후에도 예산을 넘으면 무제한으로 원문을 붙이지 않고 자료 축소나 새 세션 시작을 안내합니다.

이 검토안은 추가 요약 저장 필드·동시성 처리·생성 경로가 필요한 별도 변경입니다. 현재 코드에 자동 압축이나 위 16,000/12,000/2,000토큰 예산을 적용했다고 해석하면 안 됩니다.
