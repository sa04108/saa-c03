# 대화 맥락과 입력 예산

## 현재 적용된 동작

하나의 세션은 `ai_conversations`의 학습 자료(`context`)와 그 세션의 `ai_chat_turns`를 유지합니다. 계정 연동 사용자의 요청은 서버가 소유권을 확인하고 **학습 자료 + 세션 요약 + 아직 요약하지 않은 원문 + 현재 질문**으로 구성합니다. 요약 때문에 원본 메시지를 바꾸거나 삭제하지 않으며, 기록 화면에서도 전체 대화를 계속 볼 수 있습니다. 다른 세션의 내용은 섞지 않습니다.

- 학습 자료 본문은 최대 12,000자, 현재 질문은 최대 2,000자입니다.
- 계정 연동 세션의 입력 예산은 지침·자료·요약·원문·현재 질문·도구 정의·검색 결과를 포함해 최대 16,000토큰입니다. 오래된 원문은 필요할 때 세션별로 요약합니다.
- 익명 사용자는 기존처럼 브라우저의 최근 3쌍, 메시지마다 최대 2,000자만 전달합니다. 서버 기록과 자동 요약은 제공하지 않습니다.
- Tavily 검색 시 최대 5개 × 1,600자와 출처 정보도 입력 예산에 포함합니다.

브라우저 요청 본문은 UTF-8 기준 64 KiB까지 허용합니다. 계정 사용자의 과거 대화는 브라우저가 다시 업로드하지 않고 서버가 DB에서 읽습니다. 문자·바이트·토큰은 서로 다른 단위이므로 실제 Gemini `countTokens` 결과로 입력 예산을 검사합니다.

**이 동작을 운영에 적용하려면 [세션 압축 SQL](../supabase/migrations/202610310004_session_compaction.sql)을 실행하고 최신 Edge Function과 프런트엔드를 배포해야 합니다.** 저장소 변경만으로 운영 Supabase가 갱신되지는 않습니다.

## Google에서 확인한 모델 한도

2026-10-31에 `GET https://generativelanguage.googleapis.com/v1beta/models/{model}`로 조회한 `inputTokenLimit`·`outputTokenLimit` 값입니다. [공식 Models API](https://ai.google.dev/api/models)를 기준으로 하며, 모델 변경 시 다시 확인해야 합니다.

| 모델 | 최대 입력 토큰 | 최대 출력 토큰 |
| --- | ---: | ---: |
| `gemini-3.8-flash` | 1,048,576 | 65,536 |
| `gemini-3.6-flash` | 1,048,576 | 65,536 |
| `gemini-3-flash-preview` | 1,048,576 | 65,536 |
| `gemini-3.5-flash-lite` | 1,048,576 | 65,536 |
| `gemini-3.1-flash-lite` | 1,048,576 | 65,536 |

이는 모델이 지원하는 최대 크기이며 무료 프로젝트의 TPM·RPM·RPD와는 별개입니다. 현재 앱은 대화 출력 4,096토큰, 예상 질문 출력 2,048토큰을 요청합니다. 큰 입력이 허용된다고 해서 무료 할당량 안에서 빠르게 응답한다는 뜻은 아닙니다. 모델별 Gemini 호출 시간 합계 5초 제한도 그대로 적용됩니다.

## 공식 기능과 공개 구현에서 확인한 방식

2026-10-31에 아래 공식 원문과 공개 소스를 확인했습니다. **ChatGPT·Claude·Gemini 소비자 앱의 비공개 내부 정책을 추정한 것이 아닙니다.** 제품별 API·SDK·CLI가 공개한 기능을 비교합니다.

| 제공자 | 확인된 방식 | 우리 앱에 가져올 원칙 |
| --- | --- | --- |
| [OpenAI Responses API](https://developers.openai.com/api/docs/guides/compaction) | `compact_threshold`로 서버 압축을 켜거나 `/responses/compact`를 명시적으로 호출. 재사용하는 압축 항목은 사람이 읽는 요약이 아닌 불투명한 암호화 상태이며, 반환된 창에는 보존된 원문 항목도 포함될 수 있음 | 일정 크기에 도달했을 때 압축하고 결과를 다음 요청부터 재사용. OpenAI 전용 상태를 Gemini용 일반 텍스트 요약처럼 취급하지 않음 |
| [Claude Compaction](https://platform.claude.com/docs/en/build-with-claude/compaction) | 서버가 작성한 요약 블록을 사용. 임계값 방식과 명시적 호출 방식이 있으며, 후자는 최근 원문을 남기거나 백그라운드에서 실행 가능 | 오래된 구간만 요약하고 최근 대화는 원문으로 유지. 요약 중 새로 추가된 대화는 결과 교체 시 그대로 남김 |
| [Google ADK](https://adk.dev/context/compaction/) | 토큰 임계값 또는 이벤트 간격 기반 압축과 최근 이벤트 보존을 제공. `LlmEventSummarizer` 등에 별도 모델을 지정 가능 | Gemini로 일반 텍스트 요약을 만들고, 세션별로 저장해 여러 fallback 모델에서 재사용 |
| [Gemini CLI 공개 구현](https://github.com/google-gemini/gemini-cli/blob/6814e00d6b148c3a1d57244d5d7040f7c541009d/packages/core/src/context/chatCompressionService.ts) | 오래된 이력을 요약하고 최근 부분은 유지. 확인한 소스에는 요약 후 재검증 호출과, 빈 요약·토큰이 오히려 늘어난 요약을 거부하는 처리가 있음 | 결과를 검증하고 실패하면 기존 맥락을 유지. 무료 할당량을 고려해 재검증 모델 호출을 매번 복제하지는 않음 |

Claude의 임계값 압축은 확인 시점에 기본 150,000토큰, 최소 50,000토큰이며, [Gemini CLI 설정](https://geminicli.com/docs/reference/configuration/)의 이력 창 기본값은 압축 150,000토큰·보존 40,000토큰입니다. 이는 각 제품·구현의 값이고 우리 앱의 권장값이 아닙니다. 기능 지원 모델·beta 조건·경로에 따라 다르므로 공급자 수치를 그대로 복사하지 않습니다.

### 요약도 모델 호출이며 사용량을 소비함

일반 텍스트 요약은 `기존 요약 + 새로 요약할 원문`을 모델에 보내 새 요약을 받는 생성 요청입니다. 최초 요약에서는 기존 요약 없이 원문을 보냅니다. 입력과 출력 토큰, 요청 횟수, 실행 시간이 추가됩니다. Claude도 [압축 사용량](https://platform.claude.com/docs/en/build-with-claude/compaction-on-demand#understanding-usage)을 일반 요청처럼 계산한다고 명시합니다. 요약을 다음 질문에 붙이면 그 요약은 답변 모델의 입력 토큰으로 다시 계산됩니다.

따라서 ‘요약 한 번의 추가 사용량’과 ‘이후 여러 질문에서 원문 대신 짧은 요약을 보내 줄이는 사용량’을 함께 봐야 합니다. 요약 직후 사용자가 대화를 끝내면 토큰 절감 효과를 회수하지 못할 수 있습니다. 무료 등급에서도 추가 생성은 RPM·RPD·TPM을 사용합니다. 백그라운드 실행은 화면의 대기를 줄일 뿐 사용량을 없애지 않습니다.

[Gemini의 context caching](https://ai.google.dev/gemini-api/docs/caching?hl=en)은 반복 입력의 처리를 재사용하는 별도 기능입니다. 의미를 압축하는 요약과 같지 않으며, 캐시 적중이 맥락 크기·할당량 문제를 모두 해결한다고 가정하지 않습니다. 동일한 학습 자료와 시스템 지침을 안정적인 앞부분에 두는 최적화는 가능하지만, 캐시 적중이나 무료 사용량 절감을 보장하지 않습니다.

## 우리 앱의 구현 정책

채택한 방식은 **필요할 때 실행하는 세션별 누적 요약 + 최근 원문 + Supabase 저장**입니다. 기존 Gemini REST API와 Supabase를 사용하며 OpenAI·Claude API 키나 ADK 전체 런타임을 추가하지 않습니다. 답변 모델의 기존 fallback 순서와 5초 제한은 유지합니다.

### 1. 원문과 전달할 맥락을 분리

- `ai_chat_turns`의 원본 질문·답변은 그대로 보관합니다. 요약 때문에 기록 화면의 메시지를 수정하거나 삭제하지 않습니다.
- 계정 연동 세션의 답변 입력은 서버에서 소유권을 확인한 후 `학습 자료 + 저장된 요약 + 아직 요약하지 않은 대화 + 현재 질문`으로 구성합니다. 서버에 저장하지 못한 이전 답변은 브라우저가 저장을 재시도하며, 재시도가 실패하면 다음 질문 전송을 보류합니다.
- 최근 3쌍은 원문으로 남기는 기본 목표입니다. 계정 사용자의 고정 3쌍 창을 해제하고, 짧은 대화는 입력 예산 안에서 아직 요약하지 않은 원문을 함께 보냅니다. 입력 예산을 이미 넘긴 경우에는 최근 1쌍을 남기고 그 앞의 완료된 대화를 요약 대상으로 삼습니다. 문장을 일률적으로 앞 2,000자에서 자르는 것을 장기 기억 정책으로 삼지 않습니다.
- 학습 자료는 세션의 원본 자료로 따로 유지합니다. 매 요약에 동일한 문제 본문을 반복해서 넣거나 요약의 표현으로 원문을 덮어쓰지 않습니다. 과거 검색 결과 전문과 반복된 출처 목록도 무조건 누적하지 않고, 필요한 결론·근거 URL·확인 시각만 남깁니다.

### 2. 실행 조건과 예산

다음 값은 구현의 초기 설정이며 운영 관측에 따라 조정할 수 있습니다. 공급자 최대 입력 한도나 사용자의 요청 횟수 제한과는 별개입니다.

| 항목 | 설정 |
| --- | --- |
| 답변 요청의 입력 예산 | 전체 최대 16,000토큰. 지침·자료·요약·원문·현재 질문·도구 정의·검색 결과 포함 |
| 요약 준비 시작 | 이번 입력의 실제 토큰과 생성된 답변 토큰 합계가 12,000 이상일 때, 답변 저장 후 실행 |
| 최근 원문 | 기본 최근 3쌍 보존. 16,000토큰 초과로 답변이 보류된 경우 최근 1쌍 보존 |
| 요약 크기 | 최대 2,000토큰. 한도까지 채우지 말고 핵심 사실만 간결하게 유지 |
| 반복 요약 억제 | 최근 3쌍 외에 요약할 완료된 왕복이 최소 4개 쌓였을 때. 입력 초과 복구는 1개부터 가능. 세션당 작업 하나, 실패 후 최소 1분 뒤 재시도 |
| 처리 대상 | 우선 계정 연동 세션. 익명 사용자는 기록을 서버에 저장하지 않는 기존 방식 유지 |

요약 실행 여부는 코드가 실제 입력 크기·생성된 답변 크기와 새 대화량으로 결정합니다. 판단을 위해 별도 LLM을 먼저 호출하지 않습니다. 12,000토큰은 요약을 준비하는 기준이며, 미완료 요약이나 큰 검색 결과 때문에 16,000토큰을 넘어도 무조건 전달한다는 뜻은 아닙니다.

계정 연동 세션은 각 후보 모델의 실제 요청을 [CountTokens API](https://ai.google.dev/api/tokens)로 검사합니다. 검색 후에는 도구 결과를 포함한 요청을 다시 검사합니다. **토큰 계산 통신 시간도 해당 모델의 기존 5초에 포함**하므로 답변 생성에 남는 시간이 줄어듭니다. 고정 문자 비율로 토큰 수를 추정하지 않으며, 계산에 실패하면 확인되지 않은 큰 입력을 그대로 보내지 않습니다. 이 초기 구현은 정확한 예산 검사를 우선합니다. 향후 계측 결과에 따라 안전한 계산 결과 재사용을 검토할 수 있습니다.

### 3. 증분 요약과 모델 선택

최초에는 최근에 남길 원문을 제외한 오래된 완료 대화를 요약합니다. 그다음부터는 **기존 요약 + 마지막 요약 이후 새로 쌓인 오래된 대화**만 보냅니다. 매번 전체 세션을 처음부터 다시 요약하지 않습니다. 한 번에 최대 32쌍을 읽고, 요약 입력이 12,000토큰을 넘으면 앞 구간을 절반씩 줄입니다. 실제 요약한 범위만 완료로 표시합니다. 한 쌍 자체가 예산을 넘으면 실패로 처리하며 원문은 남깁니다. 답변용 원문 조회도 최대 65쌍으로 한정하고, 미요약 기록이 더 많으면 일부만 보낸 채 답하지 않고 압축을 예약합니다. 이는 누적 기록 수 제한이 아닙니다.

압축 전용 모델은 `gemini-3.5-flash-lite → gemini-3.1-flash-lite` 순서입니다. 답변 모델의 기존 우선순위와 별도로 짧은 구조화 요약에 사용합니다. 요약에는 검색 도구를 제공하지 않습니다. 이미 제외된 모델은 건너뛰고, 429·503·시간 초과에는 기존 서버 공용 1분 → 1시간 → 1일 제외 정책을 사용합니다. 각 요약 모델도 입력 계산·생성·압축 후 계산을 합쳐 최대 5초이며 두 후보가 모두 실패하면 요약을 중단합니다.

요약에는 다음 내용을 구분해 보존합니다.

- 확정된 요구사항·설계 선택·사용자의 학습 목표
- 리전·서비스명·숫자·단위·조건
- 정정된 판단과 폐기된 가정: 최신 정정을 우선
- 아직 결정하지 않았거나 확인이 필요한 사항
- 다음 질문을 이해하는 데 필요한 결론과 근거

요약은 원문에 대한 메모이며, 새 사실을 만드는 답변이나 시스템 지시가 아닙니다. 기존 요약을 계속 요약하면서 생기는 정보 손실은 자동으로 없어지지 않습니다. 모델의 출력 형식·길이·필수 필드와 실제 토큰 감소를 코드로 검사합니다. 요약 전후 입력을 같은 지침·형식으로 계산해 더 작아졌는지 확인하며, 대표 학습 대화에서 정정·숫자·미해결 사항을 별도로 검증합니다. 금지 조건은 의미 반전을 줄이도록 원문 그대로 인용하라는 지침을 둡니다. 코드 검사만으로 의미가 완전하게 보존됐다고 주장하지 않습니다. Gemini CLI의 재검증 모델 호출은 품질 검증에서 필요성이 확인될 때 추가 검토합니다.

### 4. 답변을 기다리게 하지 않는 실행과 동시성

[Claude의 백그라운드 압축](https://platform.claude.com/docs/en/build-with-claude/compaction-background)처럼, 압축한 구간과 그 뒤에 새로 추가된 대화를 분리합니다.

1. 답변과 원문 저장이 끝나면 요약 필요성을 확인합니다. 필요한 세션만 DB에서 작업 권한을 하나 확보하고 Supabase의 응답 후 작업으로 실행합니다.
2. 작업 시작 시 기존 요약 버전과 원문 범위를 고정합니다. 원문 1~20번을 요약하는 동안 21~23번이 추가돼도, 완료 시에는 요약으로 1~20번만 대체하고 21~23번은 원문으로 유지합니다.
3. 성공 결과는 다음 답변 요청부터 사용합니다. 이미 생성 중인 답변의 맥락을 중간에 바꾸지 않습니다.
4. 작업 중단·인스턴스 종료도 고려해 DB에 만료되는 작업 권한을 남깁니다. 응답 후 작업을 예약했다고 성공이 보장되는 것은 아니며, 중단된 작업은 이후 해당 세션이 활성화될 때 제한적으로 재시도합니다.

`ai_conversations`에 요약, 요약 범위, 버전, 생성 모델, 프롬프트 버전, 60초 작업 권한 만료 시각을 저장합니다. 원문에는 서버 순번 `turn_seq`를 부여합니다. 기존 기록은 생성 시각·ID 순으로 순번을 채우며, 이후 저장은 세션 행 잠금으로 순번을 정합니다. 늦게 재시도한 저장도 새 순번을 받아 요약 경계 뒤에 남습니다. 작업 ID·요약 버전·처리 범위·권한 만료를 검사해 오래된 작업이 최신 요약을 덮어쓰지 못하게 합니다. 요약 갱신만으로 기록 목록의 최근 대화 시각을 바꾸지 않습니다.

### 5. 실패하거나 다음 질문이 먼저 온 경우

- 아직 16,000토큰 안에 들어가면 기존 요약과 미요약 원문으로 답변합니다. 요약이 끝날 때까지 현재 답변을 막지 않습니다.
- 빈 요약·잘못된 형식·더 커진 요약·시간 초과 결과는 저장하지 않습니다. 기존 요약과 원문은 유지하고 동일한 구간을 매 요청마다 즉시 다시 요약하지 않습니다.
- 요약이 실패하거나 미완료인데 입력 예산까지 초과하면, 과거 내용을 조용히 버린 채 전체를 기억하는 척하지 않습니다. 해당 답변 생성을 보류하고, 잠시 뒤 재시도하거나 필요한 조건을 새 세션에 옮기도록 안내합니다. 긴 자료 한 건이 원인이면 대화 요약만 반복해서는 해결되지 않습니다.
- 원문 삭제, 모델별 5초 제한 연장, 사용자별 추가 일일 요청 제한으로 처리하지 않습니다. 요약 요청도 Google의 기존 프로젝트 할당량을 사용한다는 사실은 그대로입니다.

## 실제 Gemini로 확인한 결과

2026-10-31, 개인정보 없는 가상의 AWS 학습 대화로 구현의 토큰 계산·요약·재요약을 실행했습니다. Google API는 실제 호출했고 DB 저장은 모의 처리했습니다. 운영 Supabase의 지연을 포함한 측정은 아닙니다.

| 항목 | 첫 요약 | 기존 요약 + 새 대화 6쌍 |
| --- | ---: | ---: |
| 요약 생성 입력 | 7,525토큰 | 1,533토큰 |
| 생성 출력 | 379토큰 | 379토큰 |
| 요약 후 같은 형식으로 계산한 입력 | 514토큰 | 514토큰 |
| 토큰 계산까지 포함한 실행 시간 | 약 2.26초 | 약 1.74초 |

저장된 요약을 이용한 후속 답변도 실제 Gemini에서 확인했습니다. 최종 리전·파일 크기·변경된 예산·미정인 처리 엔진을 답변에 반영했고, 토큰 계산을 포함해 약 1.09초가 걸렸습니다.

첫 원문 32쌍은 15,749토큰이어서 앞 16쌍만 요약하고 나머지는 원문으로 남기는 경로를 확인했습니다. 리전 `ap-northeast-2`, 파일 한도 `500 MB`, 미정인 Lambda/ECS 선택이 남았으며, 다음 요약에서 예산 정정 `25 USD → 30 USD`가 반영됐습니다.

초기 실측에서 금지 조건이 이중 부정으로 바뀐 사례를 발견했습니다. 금지 조건은 원문을 그대로 인용하도록 지침을 보강한 뒤 동일 사례에서 원래 의미가 유지되는 것을 확인했습니다. 소수의 가상 대화 결과이므로 무손실 압축이나 모든 입력의 5초 내 성공을 보장하지 않습니다. 원문은 계속 보관하며 요약이 실패하면 교체하지 않습니다.

## 적용과 검증 범위

[세션 압축 SQL](../supabase/migrations/202610310004_session_compaction.sql)은 기존 모델 실패 제외 정책 SQL 이후에 실행합니다. 원본 기록·계정별 RLS·기존 저장 RPC를 유지하며 순번과 요약 상태, 서버 전용 읽기·작업 예약·결과 저장 함수를 추가합니다. SQL을 적용한 뒤 최신 `study-assistant` Edge Function을 배포합니다.

작업 환경에서 기존 기록이 있는 DB의 마이그레이션, 저장 재시도, 중복 작업, 작업 중 새 메시지 추가, 오래된 결과 거부, 계정 권한과 익명 차단을 검증했습니다. Edge Function은 서버 기록 사용, 입력 초과 보류, 검색 결과를 포함한 토큰 계산, 잘못되거나 더 커진 요약 거부, 429·5초 초과 fallback을 검증했습니다. 검증 코드는 저장소에 포함하지 않습니다.

공급자 지연과 요약 품질은 입력에 따라 달라집니다. 백그라운드 실행의 완료나 요약의 무손실 보존을 보장하지 않으며, 실제 Supabase 운영 환경에 SQL·함수를 적용한 검증과 장기간의 품질 관측은 별도로 필요합니다.
