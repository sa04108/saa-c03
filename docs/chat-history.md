# 계정별 AI 대화 기록

GitHub 계정을 연동한 사용자는 대화 기록을 Supabase에 저장하고 다른 기기에서 이어갈 수 있습니다. 익명 사용자는 기록 저장·조회가 불가능합니다. AI 어시스턴트의 연필 버튼 왼쪽에 있는 기록 버튼을 누르면 **세션별 대화 목록**이 나타납니다.

각 카드에는 첫 질문으로 만든 제목, 관련 문제·개념, 마지막 대화 시각이 표시됩니다. 최근에 대화한 세션부터 정렬하며 **이전 대화 불러오기**로 더 볼 수 있습니다. 카드를 선택하면 그 세션의 학습 자료와 질문·답변을 복원하고 같은 세션에서 이어서 질문합니다. **새 대화**는 별도의 자유 질문 세션을 시작합니다. 날짜와 시간은 사용 중인 기기의 시간대를 기준으로 표시합니다.

문제·개념·퀴즈의 AI 버튼은 계정과 항목 ID를 기준으로 기존 대화를 이어갑니다. 같은 항목의 대화가 여러 개 있으면 가장 최근 대화를 사용하며, 과거 기록을 합치거나 삭제하지 않습니다. 새로고침·다른 기기에서도 같은 규칙을 적용합니다. 익명 사용자는 현재 페이지에서 메모리에 남아 있는 대화만 이어가며 서버에 저장하지 않습니다.

문제집에서는 **정답·해설 확인 후 사용자가 선택한 보기**에 `AI에 물어보기` 버튼을 표시합니다. 정답 여부와 무관하며 여러 보기를 선택했다면 각각 표시합니다. 누르면 해당 보기가 맞거나 틀린 이유와 참고 답안의 오류 여부를 묻는 질문을 바로 전송합니다. 문제 상단의 AI 버튼은 기존처럼 예상 질문을 제시합니다.

## 대화 제목 수정

각 대화 카드 안 우측 하단의 연필은 기존 제목을 전체 선택된 입력란으로 바꿉니다. 오른쪽 마술 연필은 같은 제목 자리에서 점 애니메이션으로 기다린 뒤, AI가 생성하는 텍스트를 SSE로 실시간 표시합니다. 두 방식 모두 **체크 아이콘(확인)**을 눌러야 저장하며 **취소**하면 원래 제목을 유지합니다. AI 생성 도중이나 스트림이 끊긴 경우에는 확인할 수 없습니다. 제목은 최대 100자이고, 입력란의 Enter나 포커스 이동으로 자동 저장하지 않습니다.

AI 제안은 본인 계정에 저장된 첫 질문과 최근 6개 문답의 일부만 참고합니다. 별도 웹 검색 없이 기존 모델 우선순위·fallback·쿨다운을 사용하며 Gemini 사용량과 모델 성공 횟수에 포함됩니다. 제안을 확인하지 않아도 이미 실행한 AI 호출은 사용량을 소비합니다. 아직 문답이 없는 세션은 AI 제안을 제공하지 않습니다.

제목 확인은 `ai_conversations.title`만 갱신합니다. 마지막 대화 시각, 학습 자료의 원래 제목, 질문·답변과 요약은 바꾸지 않습니다. 다른 기기에서 제목을 먼저 변경했다면 확인 시 충돌을 안내하며, 취소 후 목록을 다시 열어 최신 제목을 확인할 수 있습니다. 삭제한 세션이나 다른 계정의 세션은 수정할 수 없습니다.

DB 함수는 [제목 편집 마이그레이션](../supabase/migrations/202611030003_ai_conversation_titles.sql)에 포함되며, 최신 Edge Function과 함께 `main` 배포 시 적용합니다.

## 무료 플랜에서의 규모

2026-10-31에 확인한 [Supabase 공식 요금표](https://supabase.com/pricing) 기준입니다.

| 항목 | Free 포함량 | 이 기능과의 관계 |
| --- | --- | --- |
| PostgreSQL DB | 프로젝트당 500MB | 대화 본문·인덱스·계정·진도·예상 질문 캐시가 함께 사용 |
| 일반 전송량 | 월 5GB | 대화 목록과 본문을 읽을 때 사용 |
| 캐시된 전송량 | 월 5GB 별도 | 개인 대화 DB 조회에 합산해서 10GB로 계산하지 않음 |
| 활성 사용자 | 월 50,000명 | 다른 인증 사용자와 함께 계산 |
| Edge Function | 월 500,000회 호출 | 기존 AI 요청에서 함께 저장하며 별도 AI 호출을 만들지 않음 |
| 미사용 프로젝트 | 1주일 비활성 시 일시 정지 가능 | 무료 플랜의 운영 조건 |

텍스트 중심의 소규모 학습 사이트라면 무료 플랜으로 시작할 수 있습니다. 다만 **500MB는 사용자마다 주어지는 용량이 아닙니다.** 새 DB 자체도 약 40~60MB를 사용하며, 기존 서비스 데이터와 인덱스 공간을 남겨야 합니다.

예를 들어 대화 본문에 300MB를 쓸 수 있다고 가정하고 질문·답변 한 쌍을 평균 10KB로 잡으면, 본문만으로 약 30,000쌍, 10쌍짜리 대화 약 3,000개입니다. 이는 공식 보장량이나 사이트 제한이 아닌 계산 예시입니다. 한글 길이, PostgreSQL 압축·인덱스, 대화마다 저장하는 학습 자료, 기존 진도 사용량에 따라 실제 규모가 달라집니다. 용량은 누적되므로 무기한·무제한 저장을 무료로 보장하지는 않습니다.

[DB 용량 문서](https://supabase.com/docs/guides/platform/manage-your-usage/database-size)는 데이터와 인덱스를 DB 사용량으로 계산합니다. 500MB의 플랜 할당량과 WAL 등을 포함하는 디스크 용량은 별개입니다. 무료 조직의 할당량 초과 판단에는 프로젝트 합산 및 청구 기간 평균 사용량도 관여하므로 Dashboard의 실제 Usage를 기준으로 확인합니다. [전송량 문서](https://supabase.com/docs/guides/platform/manage-your-usage/egress)도 함께 참고하세요.

## 적용

대화 기록·요약·선택 삭제의 DB 구성은 [통합 초기 스키마](../supabase/migrations/202610310005_initial_schema.sql)에 포함되어 있습니다. 현재 운영 프로젝트는 이미 적용을 완료했으며 이후 변경은 [GitHub Actions 자동 배포](github-actions-deploy.md)로 반영합니다. 새 프로젝트의 설치는 [AI 연결 가이드](ai-assistant-setup.md)를 참고하세요.

- 답변이 완성되면 질문과 답변을 한 행에 원자적으로 저장합니다. 첫 질문을 대화 제목으로 사용하며 제목 생성에 Gemini를 호출하지 않습니다.
- 학습 자료는 대화마다 한 번만 저장합니다. 새 대화는 새로운 ID의 자유 질문으로 시작합니다. 항목을 열기만 하면 새 대화를 만들지 않습니다. 항목의 첫 질문 전송 시 DB에서 세션을 확보하므로 생성 실패 시에도 해당 세션을 다음 질문에 재사용합니다.
- 항목별 조회·생성은 [추가 마이그레이션](../supabase/migrations/202611030002_ai_context_conversation.sql)의 `resolve_ai_context_conversation`을 사용합니다. 계정·항목 단위 잠금으로 여러 기기의 동시 첫 전송을 같은 세션에 연결합니다. 기존 세션의 학습 자료와 요약은 그대로 유지합니다.
- 목록은 `ai_conversations`에서 본인 계정의 세션 20개씩 읽으며, 본문 전체 대신 제목·학습 항목 이름·종류·수정 시각만 조회합니다. 수정 시각과 ID를 함께 사용해 같은 시각의 세션도 이어 읽습니다.
- 세션을 선택하면 해당 `context`와 `ai_chat_turns`의 최근 질문·답변 20쌍을 읽습니다. **이전 대화 보기**로 해당 세션의 과거 기록을 더 불러옵니다. 이는 한 번의 조회량이며 누적 기록 수 제한이 아닙니다.
- `ai_conversations`와 `ai_chat_turns`는 그대로 유지합니다. 세션 ID로 학습 자료와 대화를 연결하며, 다른 세션의 메시지를 현재 질문에 섞지 않습니다.
- 기록 조회·삭제와 저장 재시도는 PostgREST를 직접 사용합니다. Gemini 토큰과 추가 Edge Function 호출을 소비하지 않습니다. 일반 AI 전송은 기존처럼 공유 Gemini 한도를 소비합니다.
- RLS는 본인 계정의 기록만 읽도록 제한합니다. 저장 함수는 검증된 JWT의 `auth.uid()`에서 소유자를 정하고, 익명 여부를 DB에서도 검사합니다. 같은 전송 ID로 저장을 재시도해도 중복 기록이 생기지 않습니다.
- 서버에 저장하지 못한 답변은 현재 페이지에 남고 **다시 저장**으로 재시도할 수 있습니다. 저장되기 전에 페이지를 닫으면 해당 미저장 기록은 복구할 수 없습니다. 기능 추가 전에 서버에 저장하지 않았던 대화는 복원되지 않습니다.
- 기록에는 자동 만료나 자동 삭제를 적용하지 않습니다. 계정이 삭제되면 해당 계정의 대화도 함께 삭제됩니다.

## 선택과 삭제

목록의 **편집**을 누르면 개별 세션·날짜·전체 선택이 가능합니다. 날짜 옆 체크박스는 해당 날짜의 세션을 모두 선택하거나 해제합니다. 일부만 선택했다면 날짜와 전체 선택 체크박스에 부분 선택 상태를 표시합니다. 날짜는 기존 목록과 동일하게 사용 기기의 시간대에서 본 **마지막 대화 시각**을 기준으로 합니다. 선택한 날짜의 메시지만 지우는 것이 아니라 그 날짜에 속한 세션 전체를 삭제합니다.

- 편집 시작 시 본인 계정의 세션 ID와 수정 시각만 한 번 읽습니다. 날짜와 전체 선택에는 아직 화면에 불러오지 않은 세션도 포함되며, 대화 본문을 전부 내려받지 않습니다.
- 선택 대상과 날짜는 그 시점에 고정합니다. 이후 다른 기기에서 새로 만든 세션은 포함하지 않으며, 기존 세션의 날짜가 바뀌어도 편집 도중 선택 대상이 바뀌지 않습니다.
- **선택 삭제**를 누르면 개수를 확인하고 취소하거나 삭제할 수 있습니다. SQL은 검증된 JWT의 `auth.uid()`로 소유자를 확인하고 익명 사용자는 거부합니다. 클라이언트가 다른 계정의 ID를 보내도 해당 기록은 삭제되지 않습니다.
- 한 번에 최대 200개씩 처리합니다. 앞 묶음 삭제 후 실패하면 남은 선택을 유지합니다. 서버 삭제가 끝난 뒤 응답만 유실된 경우에도 같은 ID로 안전하게 재시도합니다.
- `ai_conversations`의 제목·자료·요약을 삭제하고, 연결된 `ai_chat_turns`를 함께 삭제합니다. 현재 열거나 메모리에 보관한 삭제 대상 세션도 정리합니다. 문제 풀이 진도와 예상 질문 공용 캐시는 삭제하지 않습니다.
- 삭제한 세션이 늦은 답변 저장이나 이전 탭의 저장 재시도로 되살아나지 않도록 `ai_deleted_conversations`에 세션 ID·계정 ID만 남깁니다. 본문·제목·요약은 보관하지 않습니다. 이 식별자도 계정 삭제 시 함께 제거됩니다. 저장과 삭제는 같은 세션 잠금을 사용하며, 진행 중이던 요약 작업도 삭제된 세션에 결과를 다시 만들 수 없습니다.

## 용량 확인

SQL Editor에서 전체 DB와 대화 테이블·인덱스의 실제 크기를 확인할 수 있습니다.

```sql
select pg_size_pretty(pg_database_size(current_database())) as database_size;

select pg_size_pretty(
  pg_total_relation_size('public.ai_conversations')
  + pg_total_relation_size('public.ai_chat_turns')
  + pg_total_relation_size('public.ai_deleted_conversations')
) as chat_history_size;
```

계정 연동 사용자의 후속 질문은 서버가 해당 세션의 학습 자료·저장된 요약·미요약 원문으로 구성합니다. 긴 세션은 오래된 대화만 요약하고 최근 대화는 원문으로 유지합니다. 이 기능의 DB 구성은 [통합 초기 스키마](../supabase/migrations/202610310005_initial_schema.sql)에 포함되며 최신 Edge Function과 함께 사용합니다. 요약은 기록을 삭제하지 않으며 추가 Gemini 호출과 DB 공간을 사용합니다. 실행 조건·비용·실패 처리와 모델 한도는 [대화 맥락 정책](ai-context-policy.md)을 참고하세요.
