# 계정별 AI 대화 기록

GitHub 계정을 연동한 사용자는 대화 기록을 Supabase에 저장하고 다른 기기에서 이어갈 수 있습니다. 익명 세션은 기록 저장·조회가 불가능합니다. **첫 질문부터 후속 질문으로 이어진 전체 대화가 하나의 채팅방**입니다. 질문·답변 한 쌍마다 방을 만들지 않습니다. AI 어시스턴트의 기록 버튼은 연필 버튼 왼쪽에 있으며, 대화 제목과 마지막 활동 시각만 표시합니다. 폴더·분류·메시지별 상세 목록은 두지 않습니다.

## 무료 플랜에서의 규모

2026-10-31에 확인한 [Supabase 공식 요금표](https://supabase.com/pricing) 기준입니다.

| 항목 | Free 포함량 | 이 기능과의 관계 |
| --- | --- | --- |
| PostgreSQL DB | 프로젝트당 500MB | 대화 본문·인덱스·계정·진도·예상 질문 캐시가 함께 사용 |
| 일반 전송량 | 월 5GB | 대화 목록과 본문을 읽을 때 사용 |
| 캐시된 전송량 | 월 5GB 별도 | 개인 대화 DB 조회에 합산해서 10GB로 계산하지 않음 |
| 활성 사용자 | 월 50,000명 | 다른 인증 사용자와 함께 계산 |
| Edge Function | 월 500,000회 호출 | 기존 AI 요청에서 함께 저장하며 별도 AI 호출을 만들지 않음 |
| 미사용 프로젝트 | 1주일 비활성 시 일시 정지 가능 | 무료 플랜의 운영 조건 |

텍스트 중심의 소규모 학습 사이트라면 무료 플랜으로 시작할 수 있습니다. 다만 **500MB는 사용자마다 주어지는 용량이 아닙니다.** 새 DB 자체도 약 40~60MB를 사용하며, 기존 서비스 데이터와 인덱스 공간을 남겨야 합니다.

예를 들어 대화 본문에 300MB를 쓸 수 있다고 가정하고 질문·답변 한 쌍을 평균 10KB로 잡으면, 본문만으로 약 30,000쌍, 10쌍짜리 대화 약 3,000개입니다. 이는 공식 보장량이나 사이트 제한이 아닌 계산 예시입니다. 한글 길이, PostgreSQL 압축·인덱스, 대화마다 저장하는 학습 자료, 기존 진도 사용량에 따라 실제 규모가 달라집니다. 용량은 누적되므로 무기한·무제한 저장을 무료로 보장하지는 않습니다.

[DB 용량 문서](https://supabase.com/docs/guides/platform/manage-your-usage/database-size)는 데이터와 인덱스를 DB 사용량으로 계산합니다. 500MB의 플랜 할당량과 WAL 등을 포함하는 디스크 용량은 별개입니다. 무료 조직의 할당량 초과 판단에는 프로젝트 합산 및 청구 기간 평균 사용량도 관여하므로 Dashboard의 실제 Usage를 기준으로 확인합니다. [전송량 문서](https://supabase.com/docs/guides/platform/manage-your-usage/egress)도 함께 참고하세요.

## 적용

기존 AI 설치에는 [대화 기록 마이그레이션](../supabase/migrations/202610310003_chat_history.sql)을 한 번 실행하고 최신 [study-assistant 함수](../supabase/functions/study-assistant/index.ts)를 배포합니다. Pages 프런트엔드도 최신 버전으로 배포해야 합니다. 새 프로젝트의 전체 순서는 [AI 연결 가이드](ai-assistant-setup.md)에 있습니다.

- 답변이 완성되면 질문과 답변을 한 행에 원자적으로 저장합니다. 첫 질문을 대화 제목으로 사용하며 제목 생성에 Gemini를 호출하지 않습니다.
- 학습 자료는 대화마다 한 번만 저장합니다. 새 대화는 새로운 ID의 자유 질문으로 시작합니다. 전송하지 않은 빈 대화는 저장하지 않습니다.
- 목록은 제목·ID·시각만 20개씩 읽습니다. 선택한 대화는 최근 20쌍부터 읽고 **이전 대화 보기**로 과거 기록을 더 불러옵니다. 이는 한 번의 조회량이며 대화 개수나 누적 메시지 수 제한이 아닙니다.
- 기록 조회와 저장 재시도는 PostgREST를 직접 사용합니다. Gemini 토큰과 추가 Edge Function 호출을 소비하지 않습니다. 일반 AI 전송은 기존처럼 공유 Gemini 한도를 소비합니다.
- RLS는 본인 계정의 기록만 읽도록 제한합니다. 저장 함수는 검증된 JWT의 `auth.uid()`에서 소유자를 정하고, 익명 여부를 DB에서도 검사합니다. 같은 전송 ID로 저장을 재시도해도 중복 기록이 생기지 않습니다.
- 서버에 저장하지 못한 답변은 현재 페이지에 남고 **다시 저장**으로 재시도할 수 있습니다. 저장되기 전에 페이지를 닫으면 해당 미저장 기록은 복구할 수 없습니다. 기능 추가 전에 서버에 저장하지 않았던 대화는 복원되지 않습니다.
- 기록에는 자동 만료나 자동 삭제를 적용하지 않습니다. 계정이 삭제되면 해당 계정의 대화도 함께 삭제됩니다.

## 용량 확인

SQL Editor에서 전체 DB와 대화 테이블·인덱스의 실제 크기를 확인할 수 있습니다.

```sql
select pg_size_pretty(pg_database_size(current_database())) as database_size;

select pg_size_pretty(
  pg_total_relation_size('public.ai_conversations')
  + pg_total_relation_size('public.ai_chat_turns')
) as chat_history_size;
```

큰 대화 기록을 매번 내려받거나 모든 대화를 Gemini에 보내지 않습니다. 불러온 기록이 길어도 Gemini에는 기존처럼 최근 3쌍만 전달합니다.
