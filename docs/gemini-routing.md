# Gemini 무료 모델 라우팅

2026-10-31 기준 [공식 모델 목록](https://ai.google.dev/gemini-api/docs/models), [요금표](https://ai.google.dev/gemini-api/docs/pricing), [종료 일정](https://ai.google.dev/gemini-api/docs/deprecations)을 확인했습니다. 웹의 Gemini 앱 무료 이용과 Gemini API의 무료 등급은 별개이며, 여기서는 **API 텍스트 입력·출력이 무료인 모델**을 사용합니다.

## 우선순위

[study-assistant 함수](../supabase/functions/study-assistant/index.ts)의 `geminiModels` 배열에 다음 순서를 하드코딩했습니다. 기존 `GEMINI_MODEL` 환경변수는 사용하지 않습니다.

| 순서 | 모델 ID | 선정 이유 |
| --- | --- | --- |
| 1 | `gemini-3.8-flash` | Google이 가장 지능적인 Flash 모델로 소개하는 최신 정식 모델 |
| 2 | `gemini-3.6-flash` | 이전 세대 정식 Flash, 복잡한 추론·에이전트 작업에 적합 |
| 3 | `gemini-3-flash-preview` | 무료로 사용 가능한 일반 Flash 모델, 설명·추론을 우선해 Lite보다 앞에 배치 |
| 4 | `gemini-3.5-flash-lite` | 최신 정식 Lite, 고속·대량 작업에 적합 |
| 5 | `gemini-3.1-flash-lite` | 이전 세대 정식 Lite, 마지막 대체 모델 |

이는 공식 설명을 바탕으로 **이 사이트의 학습 설명·추론을 우선한 운영 순서**입니다. Google이 발표한 모든 과제에 공통인 성능 순위는 아닙니다. 3 Flash는 preview이므로 동작·제공 조건이 바뀔 수 있으며, 3.1 Flash-Lite의 공지된 가장 이른 종료일은 2027-05-07입니다. 변경 시 모델 목록과 공식 공지를 함께 확인합니다.

- `gemini-4-argon`, `gemini-3.1-pro-preview`: API 무료 입력·출력 미제공으로 제외
- Gemini 2.5 계열: 요금표에는 무료 등급이 있지만 현재 기존 사용 이력이 있는 사용자로 접근이 제한되어 기본 후보에서 제외
- `gemini-3.7-flash`, `gemini-3.5-flash`: 각각 3.8 Flash, 3.6 Flash로 자동 라우팅되는 별칭이므로 별도 fallback 후보로 중복 등록하지 않음
- 음성·이미지·영상 전용 모델: 현재 텍스트 학습 대화 용도에 맞지 않아 제외

모든 후보는 구조화 출력을 지원합니다. 공통으로 지원하는 `thinkingLevel: low`를 사용하며, 3.8 Flash가 지원하지 않는 `minimal`은 사용하지 않습니다. 추론 토큰 공간을 포함해 예상 질문은 최대 2,048 출력 토큰, 대화는 4,096 출력 토큰을 요청하며 화면에 반환할 텍스트의 기존 길이 검증은 유지합니다.

## 스트리밍과 5초 간격 호출

1. 요청 전부터 서버 공용 제외 기간이 남은 모델은 건너뜁니다. 남은 후보를 우선순위 순서로 **0초·5초·10초·15초·20초**에 호출합니다. 앞선 모델이 오류를 반환해도 다음 호출 시각을 앞당기지 않습니다. 10초 재시도 순회는 없습니다.
2. **5초가 지나도 앞선 요청의 응답 수신을 중단하지 않습니다.** 늦게 도착한 응답도 아래 선택 기준에 따라 채택할 수 있습니다. 각 모델의 입력 토큰 계산과 생성, 검색을 포함하여 첫 모델 호출부터 **전체 30초**를 기다립니다. 인증·DB에서 맥락과 캐시를 준비하는 시간은 첫 모델 호출 전입니다. 저장과 상태 기록은 생성 이후 별도로 완료합니다.
3. **먼저 비어 있지 않은 답변 본문을 보내기 시작한 모델**을 채택합니다. 헤더·추론 텍스트·검색 함수 호출만 받은 것은 답변 시작으로 보지 않습니다. 선택 후에는 추가 호출을 예약하지 않고 다른 요청의 수신을 중단하며, 다른 모델의 텍스트를 화면이나 기록에 반영하지 않습니다. 선택한 모델이 먼저 완성될 필요는 없습니다.
4. 선택한 답변도 처음부터 계산한 30초 안에 완료되어야 합니다. 도중에 실패하거나 전체 제한을 넘으면 미완성 본문을 지우고 오류를 안내합니다. 이미 버린 다른 모델로 답변을 바꾸거나 다시 순회하지 않습니다. 모든 후보가 먼저 오류로 끝나면 30초를 채우지 않고 종료할 수 있습니다.
5. 검색은 사용자 요청당 최대 한 번 실행합니다. 동시에 여러 모델이 검색을 요청해도 같은 검색 작업을 공유합니다. 검색과 토큰 계산 시간도 30초에 포함되며 제한을 다시 시작하지 않습니다. 채택한 모델이 실제로 받은 검색 자료만 최종 답변의 출처에 추가합니다.
6. 400·401·403·404 같은 설정·인증 오류와 안전 필터 차단은 기존처럼 요청을 종료합니다. 모든 후보의 실패가 429이면 `provider_limit`, 장애·지연·전체 제한 만료가 포함되면 `provider_busy`로 안내합니다. 가장 이른 제외 해제 시각이 있으면 `retryAfter`로 전달합니다.

모든 후보가 응답하지 않을 때 1순위 모델은 최대 30초, 5순위 모델은 최대 10초 동안 응답을 보낼 수 있습니다. 단, 다른 후보가 먼저 답변을 시작하면 그 모델을 채택하므로 이 시간 전에도 나머지 수신을 중단합니다. HTTP 연결 중단은 별도의 Google 생성 작업 취소 API가 아니며, 제공자 측 생성·사용량 차감 중단을 보장하지 않습니다.

대화는 Gemini의 `streamGenerateContent?alt=sse`를 사용합니다. 브라우저가 `Accept: text/event-stream`을 보내면 Edge Function도 SSE로 중계하며, `delta`는 선택한 모델의 추가 텍스트, `reset`은 미완성 답변 폐기, `done`은 저장 결과를 포함한 최종 답변, `error`는 실패 코드와 재시도 시간을 전달합니다. `done` 없이 연결이 끊기면 완성된 답변으로 취급하지 않습니다. 기존 JSON 클라이언트도 같은 첫 본문 선택 정책을 적용하되 완성된 JSON을 받습니다.

SSE 응답이 시작된 뒤에는 HTTP 상태를 바꿀 수 없으므로 오류는 HTTP 200 스트림의 `error` 이벤트로 전달됩니다. 인증·입력 검증 등 스트림 시작 전 오류는 기존 HTTP 오류 응답을 유지합니다. 브라우저의 인증·DB를 포함한 전체 통신 정리 타이머는 기존 120초이며, 모델 생성의 30초 제한과는 별개입니다. 사용자 취소 시 진행 중인 수신과 예약된 호출을 모두 중단합니다.

예상 질문 목록은 유효한 JSON 목록을 먼저 완성한 모델을 선택합니다. 여러 생성 요청은 하나의 캐시 갱신 토큰을 공유하고, 선택한 결과의 모델 정보와 질문 목록을 함께 저장합니다. 늦은 요청은 캐시를 덮어쓰지 않습니다.

## 단계별 제외 기간

| 연속 실패 단계 | 모델 제외 기간 |
| --- | --- |
| 첫 실패 | 1분 |
| 제외 기간 종료 후 다시 실패 | 1시간 |
| 다시 실패 | 1일 |
| 이후 계속 실패 | 매번 1일 |

각 모델이 시작 후 5초 안에 첫 답변 본문을 보내지 못하면 `timeout`으로 실패 단계를 한 번 올립니다. 그 요청은 계속 기다리며, 이후 답변을 채택하더라도 이미 발생한 지연 패널티를 초기화하지 않습니다. 429·503 등 모델 오류도 기존 정책대로 기록하지만 같은 모델 시도에서 중복으로 실패 단계를 올리지 않습니다. 30초 전체 제한에 도달했다는 이유로 추가 실패 기록이나 사용자 패널티를 부여하지 않습니다. 다른 모델이 선택되어 아직 5초가 지나지 않은 요청을 중단한 경우에도 실패로 기록하지 않습니다.

실패 횟수와 제외 시각은 서버 전용 `ai_model_cooldowns`에 저장합니다. 기기·계정·Edge Function 인스턴스가 같은 상태를 공유합니다. 제외 기간이 끝나도 실패 횟수는 유지합니다. 5초 안에 답변을 시작하고 정상적으로 완료한 모델은 0으로 초기화하며, 그 뒤 다시 실패하면 1분부터 시작합니다. 캐시만 읽은 요청은 모델의 실패 횟수를 초기화하지 않습니다. 예상 질문은 유효한 목록의 완성 시각으로 5초를 판단합니다.

같은 제외 기간에 도착한 중복 실패는 단계를 올리거나 기간을 연장하지 않습니다. SQL이 행을 잠그고 원자적으로 갱신하며, 더 오래된 요청의 늦은 결과는 새 요청의 결과를 덮어쓰지 않습니다. DB 기록이 실패해도 다음 모델로 진행하지만, 요청 간 제외 기간 공유는 DB 연결 복구 후에 정상 적용됩니다.

이 기간은 사이트의 **모델 재시도 정책**입니다. Google의 실제 RPM·RPD·TPM 제한을 변경하지 않습니다. Google의 `Retry-After`나 일일 한도 초기화 시각으로 제외 기간을 늘리지 않고 위 1분 → 1시간 → 1일 순서를 사용합니다. 재시도 시 Google 한도가 남아 있으면 다시 429를 받고 다음 단계로 제외합니다.

RPM·TPM·RPD 자체를 사이트에서 새로 설정하거나 추정하지 않습니다. [AI Studio](https://aistudio.google.com/rate-limit?timeRange=last-28-days)의 프로젝트별 실제 한도를 사용합니다. 모델 변경은 사용 가능한 다른 모델을 선택하는 것이며, 프로젝트 공통 제한 등으로 모든 모델이 막혀 있으면 요청을 처리할 수 없습니다. 결제가 연결된 프로젝트에는 유료 요금이 적용될 수 있으므로 이 라우팅 자체가 무료 요금제를 강제하지는 않습니다.

## 캐시·사용량·대화 기록

- 예상 질문 캐시는 항목 ID당 한 행이고 TTL은 없습니다. 사용한 모델·프롬프트 버전·자료 지문이 재사용 여부를 결정합니다. 다른 모델로 생성하면 같은 행을 교체하며, 이전 생성의 늦은 응답은 새 모델의 캐시를 덮어쓰지 못합니다.
- 제한 중인 모델이라도 해당 모델의 유효한 예상 질문 캐시는 API 호출 없이 반환할 수 있습니다. 캐시가 없으면 대기 중인 모델을 위해 캐시를 비우거나 게스트 횟수를 차감하지 않습니다.
- 게스트는 사용자 요청당 최대 한 번만 기존 일일 횟수를 차감합니다. 5초 간격으로 최대 다섯 모델을 호출해도 한 번만 차감합니다. API 시도 전 캐시가 적중하거나 모든 모델이 이미 대기 중이라 실제 호출을 하지 않는 경우에는 차감하지 않습니다. 실제 시도 후 실패한 요청은 기존처럼 차감합니다.
- 로그인 사용자의 별도 요청 제한은 없습니다. fallback 이후 완성된 답변만 기존 채팅방에 한 번 저장합니다. 모델이 바뀌어도 새 채팅방을 만들지 않습니다.

## SQL 적용

모델 실패 횟수·제외 시각 테이블과 관련 함수는 [통합 초기 스키마](../supabase/migrations/202610310005_initial_schema.sql)에 포함되어 있습니다. 운영 프로젝트는 이미 적용을 완료했으며, 이번 통합으로 기존 모델 제외 상태를 초기화하지 않습니다.

새 프로젝트에는 빈 DB에서 초기 스키마를 적용합니다. 이후 DB와 함수 변경은 [GitHub Actions 자동 배포](github-actions-deploy.md)를 통해 `main` 반영 시 함께 배포합니다.
