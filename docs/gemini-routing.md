# Gemini 무료 모델 라우팅

2026-11-16 기준 [공식 모델 목록](https://ai.google.dev/gemini-api/docs/models), [요금표](https://ai.google.dev/gemini-api/docs/pricing), [종료 일정](https://ai.google.dev/gemini-api/docs/deprecations)과 API 모델 목록을 확인했습니다. 웹의 Gemini 앱 무료 이용과 Gemini API의 무료 등급은 별개이며, 여기서는 **API 텍스트 입력·출력이 무료인 모델**을 사용합니다.

## 우선순위

[study-assistant 함수](../supabase/functions/study-assistant/index.ts)의 `geminiModels` 배열에 다음 순서를 하드코딩했습니다. 기존 `GEMINI_MODEL` 환경변수는 사용하지 않습니다.

| 순서 | 모델 ID | 선정 이유 |
| --- | --- | --- |
| 1 | `gemini-4-hydrogen` | Google이 3.8 Flash의 업그레이드로 권장하는 최신 모델, 추론·사실 정확도·도구 활용 개선 |
| 2 | `gemini-3.8-flash` | 이전 세대의 고성능 Flash, 복잡한 추론·에이전트 작업에 적합 |
| 3 | `gemini-3.6-flash` | 정식 Flash, 범용 설명·추론과 속도의 균형 |
| 4 | `gemini-3-flash-preview` | 무료 일반 Flash, 설명·추론을 우선해 Lite보다 앞에 배치 |
| 5 | `gemini-3.5-flash-lite` | 최신 정식 Lite, 고속·대량 작업에 적합 |

이는 공식 설명을 바탕으로 **이 사이트의 학습 설명·추론을 우선한 운영 순서**입니다. Google이 발표한 모든 과제에 공통인 성능 순위는 아닙니다. [Hydrogen 업그레이드 안내](https://ai.google.dev/gemini-api/docs/whats-new-gemini-4-hydrogen)는 3.8 Flash 대비 사실 정확도 개선과 무료 등급의 GenerateContent API 지원을 명시합니다. 3 Flash는 preview이므로 동작·제공 조건이 바뀔 수 있습니다. 확인일 기준 위 5개 모델의 종료일은 공지되지 않았습니다.

- `gemini-4-carbon`, `gemini-4-argon`, `gemini-3.1-pro-preview`: API 무료 입력·출력 미제공으로 제외
- `gemini-3.1-flash-lite`: 무료 지원은 유지되지만 상위 5개 답변 후보에서 제외. 세션 압축 전용 후보인 `3.5 Flash-Lite → 3.1 Flash-Lite`는 계속 사용
- Gemini 2.5 계열: 요금표에는 무료 등급이 있지만 현재 기존 사용 이력이 있는 사용자로 접근이 제한되어 기본 후보에서 제외
- `gemini-3.7-flash`, `gemini-3.5-flash`: 각각 3.8 Flash, 3.6 Flash로 자동 라우팅되는 별칭이므로 별도 fallback 후보로 중복 등록하지 않음
- 음성·이미지·영상 전용 모델: 현재 텍스트 학습 대화 용도에 맞지 않아 제외

모든 후보는 구조화 출력을 지원합니다. 공통으로 지원하는 `thinkingLevel: low`를 사용하며, Hydrogen과 3.8 Flash가 지원하지 않는 `minimal`은 사용하지 않습니다. Hydrogen의 기본 추론 단계는 `high`이지만 현재의 응답 시간 정책에 맞춰 `low`를 명시합니다. 추론 토큰 공간을 포함해 예상 질문은 최대 2,048 출력 토큰, 대화는 4,096 출력 토큰을 요청하며 화면에 반환할 텍스트의 기존 길이 검증은 유지합니다.

## 모델 갱신 검증

2026-11-16에 설정된 API 키로 5개 모델의 토큰 계산과 짧은 한국어 SSE 응답을 확인했습니다. Hydrogen·3.6 Flash·3 Flash Preview·3.5 Flash-Lite는 응답했고, 3.8 Flash는 이 호출에서 일시적 혼잡을 뜻하는 HTTP 503을 반환했습니다. Hydrogen은 `thinkingLevel: low`에서 첫 본문까지 약 2.6초, 3.6 Flash는 약 25.3초가 걸렸습니다. 단일 짧은 요청의 결과이며 성능 순위나 운영 지연을 보장하는 측정은 아닙니다.

Hydrogen의 예상 질문 4개 구조화 출력, `search_web` 함수 호출, 모의 검색 결과를 전달한 뒤의 SSE 답변도 통과했습니다. 실제 Tavily 검색이나 운영 DB 저장은 이 검증에 포함하지 않았습니다. 별도로 실제 Edge Function 핸들러에 모의 HTTP 응답을 연결해 Hydrogen 우선 호출, 제외 중인 모델 건너뛰기, 429 발생 시 5개 후보 순회, 예상 질문 캐시에 선택된 모델을 저장하는 동작을 확인했습니다.

## 스트리밍과 5초 간격 호출

1. `available_at`이 미래인 모델은 건너뜁니다. 남은 후보를 우선순위대로 **0초·5초·10초·15초·20초**에 호출합니다. 앞선 모델이 오류를 반환해도 다음 호출 시각을 앞당기지 않습니다.
2. **5초는 다음 모델을 추가 호출하는 기준입니다.** 먼저 보낸 요청은 계속 기다립니다. 이 지연은 `ai_model_waiting` 로그에만 남으며 `failure_count`, `last_error`, `available_at`을 변경하지 않습니다.
3. **각 모델은 자신의 시작 시점부터 최대 110초**를 사용합니다. 입력 토큰 계산, 생성, Tavily 검색과 검색 후 이어쓰기를 포함하며 중간에 제한을 다시 시작하지 않습니다. 1순위는 첫 호출부터 110초, 5순위는 첫 호출부터 130초 시점에 한도에 도달합니다. 같은 30초 예산을 나눠 쓰던 정책은 제거했습니다.
4. **먼저 비어 있지 않은 답변 본문을 보내기 시작한 모델**을 채택합니다. 헤더·추론 텍스트·검색 함수 호출만 받은 것은 답변 시작으로 보지 않습니다. 선택하면 아직 시작하지 않은 호출과 다른 요청의 수신을 중단합니다. 다른 모델이 선택되어 취소된 요청에는 실패를 기록하지 않습니다. 따라서 오래 걸리는 상위 모델을 우선하여 끝까지 기다리는 정책은 아닙니다.
5. 채택한 답변도 해당 모델의 110초 안에 정상 완료해야 합니다. 본문이 도착했어도 스트림이 끝나지 않으면 성공으로 기록하지 않습니다. 도중에 실패하거나 기한을 넘기면 미완성 본문을 지우고 오류를 안내합니다. 이미 버린 다른 모델의 답변으로 교체하지 않습니다.
6. 실제 429·503 등 오류 또는 모델별 110초 초과만 실패로 기록합니다. 모든 후보가 먼저 오류로 끝나면 즉시 종료합니다. 설정·인증 오류와 안전 필터 차단은 기존처럼 요청을 종료합니다. 후보 실패가 모두 429이면 `provider_limit`, 장애·시간 초과가 섞이면 `provider_busy`로 안내하고 가장 이른 재사용 가능 시각까지의 초를 `retryAfter`로 전달합니다.

검색은 사용자 요청당 최대 한 번 수행하며 동시에 요청한 모델끼리 같은 검색 작업을 공유합니다. 선택한 모델이 실제 받은 검색 자료만 최종 답변의 출처에 추가합니다. HTTP 수신 중단은 Google 서버의 생성·사용량 차감 중단을 보장하지 않습니다.

대화와 제목 제안은 Gemini의 `streamGenerateContent?alt=sse`를 사용합니다. 브라우저가 SSE를 요청하면 Edge Function이 `delta`(추가 텍스트), `reset`(미완성 본문 폐기), `done`(정상 완료), `error`(실패)를 전달합니다. 대기 중에는 15초마다 SSE 주석을 보내 중간 프록시의 유휴 연결 종료를 줄입니다. 주석은 답변 본문이 아니며 모델 성공으로 집계하지 않습니다. `done` 없이 연결이 끊기면 완성된 답변으로 취급하지 않습니다. 기존 JSON 클라이언트에도 같은 모델 선택 정책을 적용합니다.

예상 질문은 유효한 JSON 목록을 먼저 완성한 모델을 선택합니다. 후보들은 하나의 캐시 갱신 토큰을 공유하고 선택한 결과의 모델 정보와 질문 목록을 함께 저장합니다. 늦게 도착한 다른 결과는 캐시를 덮어쓰지 않습니다.

### 무료 Supabase의 실행 시간

2026-11-16에 확인한 [공식 제한](https://supabase.com/docs/guides/functions/limits)은 무료 플랜의 worker 실행 시간 150초, 유료 플랜 400초, 요청 유휴 제한 150초입니다. 현재 프로젝트는 무료 플랜이므로 5분 대기는 제공하지 않습니다. 20초의 순차 호출 간격 + 마지막 모델의 110초 대기를 고려해 인증·저장 여유를 둡니다.

서버에는 요청 처리 시작부터 **140초 안전 상한**도 있습니다. 인증·DB 준비가 오래 걸리면 모델의 남은 110초보다 먼저 종료될 수 있지만, 이때 아직 기한이 남은 모델에 실패를 기록하지 않습니다. Supabase worker가 이미 실행 중이던 시간이나 플랫폼 종료까지 제어할 수는 없습니다. SSE 주석과 `waitUntil`도 worker의 실행 시간을 연장하지 않습니다. 백그라운드 요약은 남은 서버 예산 안에서만 시작합니다.

브라우저의 통신 정리 타이머는 인증·네트워크 시간을 포함해 **180초**입니다. SSE 시작 후 오류는 HTTP 200 스트림의 `error` 이벤트로 전달하며, 시작 전 오류는 HTTP 오류 응답으로 전달합니다. 사용자 취소는 진행 중인 요청과 예약된 호출을 정리하며 모델 실패로 집계하지 않습니다.

## 단계별 제외 기간

| 연속 실패 단계 | 모델 제외 기간 |
| --- | --- |
| 첫 실패 | 1분 |
| 제외 기간 종료 후 다시 실패 | 1시간 |
| 다시 실패 | 1일 |
| 이후 계속 실패 | 매번 1일 |

실패 횟수와 제외 시각은 서버 전용 `ai_model_cooldowns`에서 기기·계정·Edge Function 인스턴스 전체가 공유합니다. 제외 기간이 끝나도 실패 횟수는 유지합니다. 같은 제외 기간에 겹친 요청들의 오류는 한 단계로 처리합니다.

정상 완료한 최신 요청은 `failure_count = 0`, `last_error = null`, `available_at = 현재 시각`으로 회복합니다. 5초 지연에 임시 실패를 추가하지 않으므로 성공 시 되돌릴 임시 증가분도 없습니다. `last_attempt_started_at`으로 순서를 확인해 오래된 성공이 더 최근 요청의 오류를 지우거나, 오래된 오류가 더 최근 성공을 덮어쓰지 못하게 합니다.

`success_count`는 채택된 정상 답변·예상 질문·검증된 세션 요약을 각각 한 번 집계합니다. 늦어도 자신의 기한 안에 정상 완료하면 성공입니다. 캐시 조회, 토큰 계산, 검색 중간 응답, 취소·미완성 답변은 제외하고 누적 성공 횟수는 초기화하지 않습니다.

백그라운드 세션 요약의 모델당 5초는 짧은 작업 예산입니다. 이를 넘겨 요약을 중단하는 것은 답변 모델의 실패가 아니므로 공용 실패 횟수를 올리지 않습니다. 요약 중 실제 HTTP·네트워크 오류는 기록합니다.

[`202611160001_model_availability.sql`](../supabase/migrations/202611160001_model_availability.sql)은 `retry_at`을 `available_at`으로 변경하고 관련 RPC를 갱신합니다. 과거 짧은 기한으로 생긴 `timeout` 제외 상태만 해제하며 실제 HTTP·네트워크 오류와 `success_count`는 보존합니다. 기존 자동 배포가 SQL을 적용한 뒤 새 함수를 배포합니다. 이전 마이그레이션 파일은 배포 이력이므로 수정하지 않습니다.

이 기간은 사이트의 **모델 재시도 정책**입니다. Google의 실제 RPM·RPD·TPM 제한을 변경하지 않습니다. Google의 `Retry-After`나 일일 한도 초기화 시각으로 제외 기간을 늘리지 않고 위 1분 → 1시간 → 1일 순서를 사용합니다. 재시도 시 Google 한도가 남아 있으면 다시 429를 받고 다음 단계로 제외합니다.

RPM·TPM·RPD 자체를 사이트에서 새로 설정하거나 추정하지 않습니다. [AI Studio](https://aistudio.google.com/rate-limit?timeRange=last-28-days)의 프로젝트별 실제 한도를 사용합니다. 모델 변경은 사용 가능한 다른 모델을 선택하는 것이며, 프로젝트 공통 제한 등으로 모든 모델이 막혀 있으면 요청을 처리할 수 없습니다. 결제가 연결된 프로젝트에는 유료 요금이 적용될 수 있으므로 이 라우팅 자체가 무료 요금제를 강제하지는 않습니다.

## 캐시·사용량·대화 기록

- 예상 질문 캐시는 항목 ID당 한 행이고 TTL은 없습니다. 사용한 모델·프롬프트 버전·자료 지문이 재사용 여부를 결정합니다. 다른 모델로 생성하면 같은 행을 교체하며, 이전 생성의 늦은 응답은 새 모델의 캐시를 덮어쓰지 못합니다.
- 제한 중인 모델이라도 해당 모델의 유효한 예상 질문 캐시는 API 호출 없이 반환할 수 있습니다. 캐시가 없으면 대기 중인 모델을 위해 캐시를 비우거나 게스트 횟수를 차감하지 않습니다.
- 게스트는 사용자 요청당 최대 한 번만 기존 일일 횟수를 차감합니다. 5초 간격으로 최대 다섯 모델을 호출해도 한 번만 차감합니다. API 시도 전 캐시가 적중하거나 모든 모델이 이미 대기 중이라 실제 호출을 하지 않는 경우에는 차감하지 않습니다. 실제 시도 후 실패한 요청은 기존처럼 차감합니다.
- 로그인 사용자의 별도 요청 제한은 없습니다. fallback 이후 완성된 답변만 기존 채팅방에 한 번 저장합니다. 모델이 바뀌어도 새 채팅방을 만들지 않습니다.

## SQL 적용

모델 실패 횟수·제외 시각 테이블과 관련 함수는 [통합 초기 스키마](../supabase/migrations/202610310005_initial_schema.sql)에 포함되어 있습니다. 운영 프로젝트는 이미 적용을 완료했으며, 이번 통합으로 기존 모델 제외 상태를 초기화하지 않습니다.

새 프로젝트에는 빈 DB에서 초기 스키마를 적용합니다. 이후 DB와 함수 변경은 [GitHub Actions 자동 배포](github-actions-deploy.md)를 통해 `main` 반영 시 함께 배포합니다.

성공 횟수 집계는 [추가 마이그레이션](../supabase/migrations/202611030001_ai_model_success_count.sql)으로 적용합니다. 기존 모델의 제외 상태를 유지하며 과거 성공 횟수는 소급 집계하지 않습니다. 새 프로젝트에도 초기 스키마 다음에 적용합니다.
